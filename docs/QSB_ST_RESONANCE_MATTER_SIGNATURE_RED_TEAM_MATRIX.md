# QSB-ST Resonance Matter Signature
## Red-Team Matrix for the Current Bridge Architecture

QSB-ST currently has a coherent bridge-architecture chain:

relational correlation without assumed spacetime
-> relational dynamics and phase
-> de-Broglie motivated phase/interference/correlation
-> Gram/Graph geometric readability
-> Green/Poisson, Coulomb-like, VDW, Hartman, and Relational Delay anchors
-> Matter Signature and Carbon calibration lines.

This matrix intentionally attacks the chain to identify weak links, not to dismiss the project. It follows the project communication principle: "Die Idee ins Licht. Die Grenzen ans Geländer. Die Details in den Maschinenraum." Because this is a red-team document, the wording is direct, critical, and oriented toward useful next work.

## 1. Purpose

This document is a reviewer-facing and internal architecture stress test for the current QSB-ST Resonance Matter Signature bridge architecture.

It is not a result note and not a new theory proof. Its purpose is to expose the most important weak links, separate claim levels, and define next clarifications before stronger synthesis language is used.

## 2. Current architecture under attack

The current architecture asks whether stable, phase-coherent relational correlation structures can remain readable under geometry, interaction, delay, and matter-signature tests.

The main chain under attack is:

- relational correlation without assumed spacetime;
- relational dynamics and phase;
- de-Broglie motivated phase/interference/correlation;
- Gram/Graph geometric readability;
- Green/Poisson, Coulomb-like, VDW, Hartman, and Relational Delay anchors;
- Matter Signature and Carbon calibration lines.

The red-team position is that each arrow in this chain must be justified separately. A readable graph, a stable phase, a successful benchmark, or a useful scanner control is not automatically a physical bridge.

## 3. Red-team summary

The architecture is strongest as a candidate bridge architecture / translation layer: it organizes relational phase, geometric readability, interaction-like anchors, delay-like anchors, and matter-signature diagnostics into one work program.

The architecture is weakest where a mathematical readout is at risk of being mistaken for a physical observable. The highest-risk gaps are physical anchoring, Lorentz / continuum-limit status, marker-vs-carrier separation, de-Broglie specificity beyond weak controls, and provenance cleanup for archival Matter Signature results.

## 5. Highest-priority Sollbruchstellen

1. Physical Anchor Problem

   D(A,B) and related reconstructed distances need independent observable anchors and scaling laws. Without that, the architecture has geometric readability, not physical geometry.

2. Carrier / Marker Distinction

   The project must classify which structures are marker layers, candidate carrier axes, diagnostics, or interpretive summaries. This affects K_ij, `|K|`, G, D_rel, weighted relational structure, negative/abs, VDW, Matter Signature, and Carbon diagnostics.

3. Lorentz / Continuum-Limit Status

   Lorentz structure must be labeled as assumption, definition, derived-within-assumptions result, or interpretation. This is a critical reviewer pressure point.

4. de-Broglie Specificity

   Random/trivial controls are not enough to establish specificity. The next control layer should include structured non-de-Broglie, spectrum-matched, and energy/momentum-shuffled phases.

5. Provenance / Canonical Rerun of archival Matter Signature results

   The recovered duplicate-quarantine Matter Signature cluster is useful, but it is not yet a canonical current result. It needs artifact mapping, input/config recovery, and replay criteria.

6. Coupling hierarchy across geometry, interaction, and delay anchors

   Green/Poisson, Coulomb-like, VDW, Hartman, Shapiro, and Relational Delay anchors need a hierarchy that says which axis each anchor tests and how the axes connect.

## 6. Claim-safe wording

Recommended phrases:

- "geometrically readable candidate structure"

- "shared negative/abs upper block"
- "scanner calibration and mimicry discipline"

Avoid upgrading these phrases into physical validation language unless the relevant anchor, control, and reproducibility requirements have been met.
