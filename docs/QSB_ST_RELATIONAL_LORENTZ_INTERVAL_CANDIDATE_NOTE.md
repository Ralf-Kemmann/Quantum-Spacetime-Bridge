# QSB-ST Resonance Matter Signature
## Relational Lorentz Interval Candidate Note

Guiding principle:

"Die Idee ins Licht. Die Grenzen ans Geländer. Die Details in den Maschinenraum."

## 1. Purpose

This note opens a cautious but important theory question for QSB-ST: whether the current relational architecture can define a candidate interval from reconstructed distance, relational delay, and phase structure. The positive aim is to locate a testable place where Lorentz-like structure could become visible without treating old toy-model language as a completed derivation.

This is not a proof of Lorentz invariance, not a derivation of relativity, not a result note, and not a numerical implementation. It is a working architecture note for a candidate interval readout.

The aim is not to claim that QSB-ST has derived Lorentz transformations, but to ask whether the current relational architecture contains a testable place where a Lorentz-like interval structure would have to appear if the Bridge is physically meaningful.

Ziel ist nicht zu behaupten, QSB-ST habe die Lorentz-Transformationen bereits abgeleitet, sondern zu prüfen, ob die heutige relationale Architektur einen testbaren Ort enthält, an dem eine Lorentz-artige Intervallstruktur sichtbar werden müsste, falls die Bridge physikalisch tragfähig sein soll.

## 2. Why this question matters

The project should now ask whether a Lorentz-like relational invariant can be formulated and tested inside QSB-ST. This is one of the deepest bridge questions, but it must be asked cautiously; otherwise QSB-ST remains only a diagnostic toy/scanner framework.

A candidate interval would connect three current architecture lines:

- Geometry Anchor: whether a reconstructed distance can be read geometrically.
- Relational Delay and causality discipline: whether a delay-like object has operational meaning without becoming a causal claim.
- Lorentz Status discipline: whether Lorentz-like language is compatible, inspired, assumed, candidate-emergent, or not Lorentz-derived.

## 3. Starting point from the older Part II work

The older document "Part II - Relationale Dynamik und Simulationen" introduced `K_ij(t)` as a time-dependent relational correlation matrix. Its dynamics was explicitly described as an effective toy model.

In that older framing, linearization plus continuum-limit assumptions led to an effective wave-equation-like structure. The simulations were framed as exploratory consistency tests, not physical validation.

The old Lorentz paragraph stated formal Lorentz invariance of the effective wave equation and treated Lorentz structure as given from Part I. It also stated that Part I had selected Lorentz transformations through observer-independent relational phase dynamics.

Current QSB-ST should read that passage cautiously. Unless the stronger derivation is explicitly reconstructed, the current status is Lorentz-compatible / Lorentz-inspired / DERIVATION-WITHIN-ASSUMPTIONS, not Lorentz-derived in the strong sense.

## 4. Current status correction

Using the Status-/Claim-Taxonomy:

- `K_ij(t)`: DEFINITION / relational correlation object.
- toy dynamics: MODEL ASSUMPTION.
- linearization and continuum limit: DERIVATION-WITHIN-ASSUMPTIONS.
- effective wave-equation-like structure: DERIVATION-WITHIN-ASSUMPTIONS.
- relational phase: CANDIDATE DYNAMICAL READOUT / HEURISTIC.
- formal Lorentz invariance of chosen/effective wave equation: LORENTZ-COMPATIBLE / LORENTZ-ASSUMED or DERIVATION-WITHIN-ASSUMPTIONS depending on reconstruction.
- Lorentz transformation derived from relational structure: NOT ESTABLISHED.

This correction preserves the older work as a useful theory source while keeping the current status clear.

## 5. The central question

Can QSB-ST define a relational interval candidate from reconstructed distance and relational delay such that this quantity remains stable under admissible frame/readout transformations?

Kann QSB-ST einen relationalen Intervallkandidaten aus rekonstruierter Distanz und relationalem Delay definieren, der unter zulässigen Frame-/Readout-Transformationen stabil bleibt?

The question is deliberately about a candidate interval, not a physical spacetime interval. It asks whether a combined distance-delay diagnostic is more stable than either component alone under controlled transformations.

## 6. Candidate ingredients

1. `D(A,B)`: Current status is reconstructed graph/cost distance readout. It needs Geometry Anchor support before physical distance language is used.
2. `d_ij = -l0 log |K_ij|`: Current status is candidate relational distance readout. It needs explicit `l0` handling and an external anchor.
3. `tau_rel(A,B)`: Current status is relational-delay candidate, not physical time interval. It needs delay-readability, asymmetry, and operational meaning.
4. phase / relational phase: Current status is candidate dynamical readout. It needs PADS-01 and structured phase controls.
5. `c_eff`: Current status is effective scale / propagation parameter. It is not automatically physical `c`. It must be fixed by convention, calibrated, derived, or sensitivity-reported.
6. `S_rel^2`: Current status is candidate interval readout. It is not an established spacetime interval.

These ingredients should be declared before any future test. Changing them after seeing results would turn LIC-01 into score engineering rather than a claim-discipline test.

## 7. Relational interval candidate

A cautious working form is:

```text
S_rel^2(A,B) = c_eff^2 * tau_rel(A,B)^2 - D(A,B)^2
```

This is a candidate diagnostic object, not a physical invariant. Its purpose is to test whether a combined distance-delay object is more stable than distance or delay alone under controlled transformations.

Possible variants:

- `D(A,B)` may be replaced by `d_ij` only if `l0` handling is explicit.
- `tau_rel` may be phase-gradient-based, delay-readout-based, or relational-shift-based, but its construction must be declared before testing.
- `c_eff` may be free, calibrated, or fitted; fitted `c_eff` must be reported as a fit, not validation.

The useful question is not whether the formula looks Lorentz-like. The useful question is whether its behavior is invariant-like under declared readout/frame-like transformations and stronger than its separate components.

## 8. What would count as Lorentz-like evidence

Lorentz-like evidence for a candidate interval would include:

- `S_rel^2` remains more stable than `D` or `tau_rel` alone under admissible readout/frame transformations.
- Stability survives backbone/pipeline variation.
- Stability survives phase/amplitude controls.
- Random/trivial/spectrum-matched phase controls fail to reproduce it.
- Label/family shuffles fail to reproduce it.
- Geometry Anchor conditions are met for `D(A,B)`.
- Delay-readability criteria are met for `tau_rel`.
- `c_eff` handling is predeclared.
- Null models do not explain the invariant-like behavior.
- The result can be reproduced in a canonical test.

Such evidence would support candidate or invariant-like language. It would not by itself prove Lorentz covariance or establish a physical metric.

## 9. What would not count

The following would not count as Lorentz-like evidence:

- merely observing a wave equation,
- choosing a Lorentz-invariant equation and claiming derivation,
- fitting `c_eff` post hoc,
- seeing stable `D(A,B)` alone,
- seeing stable `tau_rel` alone,
- seeing graph geometry without external anchor,
- seeing phase structure without PADS-01 controls,
- reading correlation as causality,
- reading delay as light cone,
- reading `S_rel^2` as spacetime interval before anchoring.

These are useful warnings because the older Part II language is close to strong Lorentz language and must now be read through the current status discipline.

## 10. Candidate frame / readout transformations

At the current stage, admissible transformations are readout/frame-like transformations, not physical Lorentz transformations.

Possible readout/frame-like transformations include:

- backbone method variation,
- threshold / edge-count variation,
- cost-function variation,
- rescaling of `D` and `tau_rel` with declared `c_eff` handling,
- phase gauge-like shifts that preserve phase differences,
- relabeling controls that should not preserve structure if labels carry physical meaning,
- observer/readout-like transformations only as future formal objects, not yet true inertial-frame transformations.

The point of these transformations is modest: test whether the candidate interval has stability not explained by pipeline choice, graph artifact, phase triviality, or label leakage.

## 12. Relationship to Geometry Anchor Conditions

No relational interval candidate can be physically interpreted unless its distance component has passed Geometry Anchor requirements or is explicitly kept at diagnostic-readout status.

`D(A,B)`, `d_ij`, and `D_rel` can support LIC-01 only if their source, scaling, `l0` handling, nulls, and external anchor status are recorded. Without that, `S_rel^2` stays a candidate interval readout only.

## 13. Relationship to Relational Delay and Causality

`tau_rel` is not time. Relational delay is a candidate structured shift between correlation patterns.

Causality requires asymmetry, perturbation response, no-signalling compatibility, and operational testability. No LIC-01 result may claim causal cones unless a separate causal-cone criterion is defined.

The interval candidate may test delay-readability, but delay-readability is not causal order.

## 14. Relationship to PADS-01 and Marker-vs-Carrier discipline

If `S_rel^2` stability depends on phase organization, PADS-01 is needed to test phase vs amplitude vs label/pipeline effects.

`S_rel^2` is a diagnostic object / interval candidate, not a carrier. The candidate carrier remains phase-coherent off-diagonal relational correlation structure unless future criteria justify an upgrade.

Marker-vs-Carrier discipline matters here because an elegant interval formula can still be only a readout. Carrier status must come from stability, specificity, controls, formalization, and anchor compatibility.

## 15. Failure and warning modes

Important failure and warning modes:

- Lorentz structure imported by equation choice.
- `c_eff` fitted post hoc.
- `D(A,B)` unanchored.
- `tau_rel` treated as physical time.
- `S_rel^2` treated as spacetime interval.
- phase controls too weak.
- label/topology leakage.
- graph geometry artifact.
- null models reproduce interval stability.
- correlation mistaken for causality.
- delay mistaken for light cone.
- old Part II wording overread as strong Lorentz derivation.

These modes should be reported in any future LIC-01 readout, including inconclusive or failed runs.
